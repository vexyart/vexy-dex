## vexy-dex

Vexy Dex is a tool that employs multiple strategies to produce slide decks (primarily in PDF format) from HTML pages.

The tool works ingesting HTML pages, classifying them into "kinds" of pages, and evaluating the optimal strategies (multiple strategies are possible) to turn the page into a slide deck: basically paginated PDF, typically in 16:9 format, but that’s customizable. 

The tool should recognize certain common patterns in the HTML pages. For example it should recognize pages 

- made by Webflow (see ./private/webflow2reveal/ for some pointers and https://www.vexy.art/lines/ and https://www.vexy.art/lines/case-retro-poster/ and https://www.fontlab.com/font-editor/fontlab/ and https://www.fontlab.com/ for examples ), 
- made by MkDocs + MkDocs Material (see `/Users/adam/Developer/vcs3/github.fontlab/blog.fontlab.com` = https://github.com/fontlab/blog.fontlab.com/ = https://blog.fontlab.com/ for an example ),  but also other tools like Bubble, Shuffle, etc.
- made by other common packages/tools 

After ingesting the page, the tool should "normalize" the page by shuffling some DOM elements around, or adding wrappers. For example, in order for reveal.js to work well, we need to wrap a series of `section` elements with two divs: 

```html
<div class="reveal">
    <div class="slides">
    <section>Slide 1</section>
    <section>Slide 2</section>
    </div>
</div>
```

This can be a single normalization, or there can be additional output-specific normalizations. 

Instead of picking just one strategy, the tool should can produce multiple variants (or 'all'). 

In general, the idea is that from a given URL, the tool emits several folders (one per strategy), and within each folder is a series of single-page PDFs (or ultimately also SVGs using https://github.com/vexyart/vexy-pdfsvgpy = /Users/adam/Developer/vcs3/github.vexyart/vexy-pdfsvgpy ). Because we’ll be using various strategies, one strategy can produce a different number of pages than another strategy. That’s normal. 

Ultimately, we leave it to the user to decide which slides from which strategy to pick. For example the user can pick the first 2 slides from strategy A (which were slides for the hero section of the page)and then some slides from strategy B (which were more text-heavy slides) to create a complete slide deck in a tool of their choosing. 

vexy-dex will be written in Python, and will work offline, mainly as a Fire CLI tool. 

It should implement: 

1. Step 1: 'readers' that focus on purely technical fetching of HTML from URLs, files etc., and also fetching assets like images, videos, etc.

2. Step 2: 'pre-importers': algorithmic decision makers, but possibly also LLM-based analyzers that decide on the importing. This may include, for example, a loop where we use the a browser to render the page at the viewport size that’s compatible with the final deck, and we somehow check which elements are visible at that viewport size. Basically we check how the browser naturally paginates the current page. But we also check for some semantics: article, section, headings. So the pre-pagination we do should not be stupid. We should ensure that before a new section, or in absenve of sections, before a high-level heading like H2, there’s the beginning of a new page, and then we check how many 'screens' are until the next such break. 

3. Step 3: 'importers': ingest the output of the readers, and apply specific preprocessors and normalizers for various kinds of HTML pages)

4. Step 4: 'pre-exporters': the middle of the process. 

5. Step 5: 'exporters': specific engines that transform the HTML into PDFs (single- or multi-page), typically

6. Step 6: 'writers': purely technical tools that take the output of an exporter and produces the single-page PDFs that are apporopriately named, and also SVGs and other assets; possibly even an HTML page that has the SVGs embedded, or an HTML page that’s made from a simple revealjs project where each input slide def is the full-page SVG. 

It should use various tools and libraries, and install them if possible. This should include: 

- https://github.com/twardoch/webflow2reveal ./private/webflow2reveal/

- vivliostyle https://vivliostyle.org/en/

- prince https://www.princexml.com/ 

- cheap local & vision models like https://github.com/OpenBMB/MiniCPM-V/blob/main/docs/api.md+ https://huggingface.co/openbmb/MiniCPM-V-4.6-gguf
