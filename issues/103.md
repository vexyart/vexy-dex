## "Offlinization" 

Here's an extensive list of JS/Node packages and related tools for "offlinization," linearization, inlining, and bundling HTML pages into self-contained files (for offline use, email, archiving, embedding, etc.).

## Single-file page archivers (offline use)

- **SingleFile** (`single-file-cli`) — Saves a complete page (HTML, CSS, images, fonts, frames) into one HTML file; available as Web Extension and Node CLI/library, with Puppeteer/Playwright back-ends. Also supports self-extracting ZIP/HTML polyglot output. [github](https://github.com/gildas-lormeau/SingleFile/)
- **Monolith** (`monolith` CLI; Rust, but with `npm i monolith` wrapper) — Bundles a target page plus CSS, images, JS, and fonts into a single HTML5 document; flags to strip JS/images/fonts/CSS. [npmjs](https://www.npmjs.com/package/monolith)
- **nodeSavePageWE** — Fork of the SavePageWE Chrome extension adapted to Node + Puppeteer; produces a self-contained single HTML file. [github](https://github.com/markusmobius/nodeSavePageWE)
- **inliner** (`@remy/inliner`) — Node utility that fetches a URL and inlines CSS, JS, images, and videos (base64), minifies JS, strips CSS whitespace, outputs one HTML file. Useful for mobile/appcache scenarios. [github](https://github.com/remy/inliner/)
- **tauri-inliner** — Maintained fork of `inliner` under the Tauri org; same single-file inlining behavior. [github](https://github.com/tauri-apps/tauri-inliner)
- **monolith (npm)** — Older Node module to aggregate CSS/JS/images and inline them into a single HTML document for high-perf HTML apps. [npmjs](https://www.npmjs.com/package/monolith)
- **mhtml2html** (`@luminati-io/mhtml2html`) — Converts MHTML archives into a single self-contained HTML document in pure JS. [npmjs](https://www.npmjs.com/package/@luminati-io/mhtml2html)
- **Puppeteer + CDP `Page.captureSnapshot`** — Not a package per se, but a common approach to produce MHTML offline archives, or to intercept `page.on('response')` and rewrite asset URLs. [stackoverflow](https://stackoverflow.com/questions/53640405/puppeteer-save-webpage-and-images)

## CSS inliners (mainly for HTML email)

- **juice** — The de-facto CSS inliner for Node; inlines `<style>`/external CSS into `style=""` attributes, can also inline external CSS, images, and JS when used from npm. [automattic.github](http://automattic.github.io/juice/)
- **juice2** — Fork of juice with extra options (preserves media queries, sorts rules, etc.). [stackoverflow](https://stackoverflow.com/questions/4894081/compile-css-into-html-as-inline-styles)
- **styliner** — Promise-based alternative to juice with `compact` minification and margin/padding shorthand expansion. [stackoverflow](https://stackoverflow.com/questions/4894081/compile-css-into-html-as-inline-styles)
- **inline-css** — Juice-inspired library; inlines CSS into the `style` attribute, designed for email and 3rd-party embedding. [npmjs](https://www.npmjs.com/package/inline-css)
- **css-inline / @css-inline/css-inline** — High-performance Rust-backed inliner with Node bindings; inlines `<style>` and `<link>` CSS, removes the originals, resolves external/local stylesheets. [npmjs](https://www.npmjs.com/package/css-inline)
- **email-css** — Takes `<link rel="stylesheet">` tags and inlines them as `<style>` blocks for email. [npmjs](https://www.npmjs.com/package/email-css)
- **juice-daily** — Juice variant that also converts CSS rules into legacy HTML attributes (`bgcolor`, `align`, `border`) for old email clients. [github](https://github.com/dailymotion/juice-daily)
- **node-email-templates** — Higher-level email rendering that uses juice under the hood for inline CSS. [github](https://github.com/brendonboshell/node-email-templates)

## Bundlers / build-tool plugins for single-file output

- **vite-plugin-singlefile** — Vite plugin that inlines all JS and CSS into the final `dist/index.html`, producing a single distributable HTML app. [npmjs](https://www.npmjs.com/package/vite-plugin-singlefile)
- **@vituum/vite-plugin-juice** — Vituum plugin wrapping juice for inlining CSS into HTML, aimed at email templates. [vituum](https://vituum.dev/plugins/juice.html)
- **html-bundle** — Zero-config bundler treating HTML files as single-file components, processing `<style>`/`<script>` blocks via PostCSS/cssnano. [github](https://github.com/Krutsch/html-bundle)
- **Modern.js inline assets** — Built-in support (via `?inline` / `?__inline` query) to force-embed images/fonts/CSS into HTML/JS instead of emitting separate files. [modernjs](https://modernjs.dev/guides/advanced-features/page-performance/inline-assets)
- **Greenwood** — Web-standards meta-framework with an optimization config that inlines JS and CSS into a single HTML output. [reddit](https://www.reddit.com/r/javascript/comments/xjk9e4/askjs_entire_app_must_compile_to_single_html_file/)
- **Webpack html-inline-plugin / single-file plugins** — Commonly used to inline scripts/styles for environments that only accept a single HTML blob (e.g., Eloqua, planning tools). [reddit](https://www.reddit.com/r/javascript/comments/xjk9e4/askjs_entire_app_must_compile_to_single_html_file/)

## Related/adjacent tools

- **node-website-scraper** — Crawls a site and rewrites links so the local copy works offline (multi-file, not single-file). [community.latenode](https://community.latenode.com/t/saving-complete-web-pages-offline-using-puppeteer/17362)
- **HTTrack** — Classic offline-browser mirror tool (not JS, but often used alongside Node pipelines). [httrack](https://www.httrack.com)
- **leaflet.offline** — Niche: caches map tiles for offline Leaflet usage in browser/PWA contexts. [npmjs](https://www.npmjs.com/package/leaflet.offline)
- **next-pwa / service workers** — For PWA-style "offline" rather than self-contained HTML, but worth noting if "offline" means cached app shell. [medium](https://medium.com/@mertenercan/nextjs-14-offline-page-with-pwa-6868c02bfefb)

## Quick decision guide

| Use case | Best fits |
|---|---|
| Archive a live URL into one HTML file | SingleFile, Monolith, inliner, nodeSavePageWE  [github](https://github.com/gildas-lormeau/SingleFile/) |
| Prepare HTML email (CSS → style attrs) | juice, css-inline, inline-css, juice2, styliner  [automattic.github](http://automattic.github.io/juice/) |
| Ship a webapp as one HTML | vite-plugin-singlefile, Greenwood, html-bundle  [npmjs](https://www.npmjs.com/package/vite-plugin-singlefile) |
| Embed images/fonts at build time | Modern.js inline assets, Vite/Webpack inline loaders  [modernjs](https://modernjs.dev/guides/advanced-features/page-performance/inline-assets) |
| Convert MHTML → HTML | mhtml2html  [npmjs](https://www.npmjs.com/package/@luminati-io/mhtml2html) |

The web was designed to be distributed, so pulling everything back into a single, self-contained file—whether for offline archiving, embeddable web apps, or email clients—requires specialized tooling.

The right package depends entirely on your end goal. Here is a comprehensive list of JavaScript packages categorized by their specific approach to "offlinization" and linearization.

## Full-Page Offlinization (Single-File Generators)

These tools are designed to take an entire web page (or local project) and aggressively bundle everything—HTML, CSS, JavaScript, Web Fonts, and Images—into one portable HTML file.

* **`single-file-cli`**: The gold standard for accurately capturing modern, dynamic web pages. It uses Puppeteer (headless Chrome) to let the page fully render before scraping the DOM and inlining all external assets into a single file.
* **`inliner`**: A classic Node.js utility by Remy Sharp. You point it at a URL or local file, and it downloads all assets, base64-encodes media, minifies the code, and reconstructs a single HTML file.
* **`inline-source`**: An HTML parser that looks for specific attributes (e.g., `<script inline src="...">`). When it finds them, it reads the linked file and replaces the tag with the raw, inlined code.
* **`web-resource-inliner`**: Similar to `inline-source`, but highly optimized for fetching remote resources via HTTP and embedding them as base64 strings or raw text inside the HTML document.

## Modern Bundler Plugins

If you are building a Single Page Application (SPA) or utility tool and want your build step to output a single file rather than a directory of assets, you need bundler-specific plugins.

* **`vite-plugin-singlefile`**: Takes a standard Vite build and forces it to output a single `dist/index.html`. It automatically converts all JS and CSS chunks into inline scripts and styles. This is incredibly useful for building offline-first utility apps that users can just double-click to open from their desktop.
* **`html-inline-script-webpack-plugin`**: Works alongside Webpack's `html-webpack-plugin` to take specified JavaScript chunks and embed them directly into the output HTML, rather than linking to external `.js` files.
* **`html-inline-css-webpack-plugin`**: The CSS equivalent for Webpack, pulling all compiled stylesheets into the `<head>` of your document.

## Email Preparation (CSS Inlining)

HTML email clients (like Outlook and Gmail) often strip out external stylesheets and `<style>` blocks. To ensure emails render correctly, CSS must be "linearized" directly into the `style="..."` attributes of individual HTML elements.

* **`juice`**: The industry workhorse for email rendering. You feed it an HTML file with a `<style>` block (or external CSS), and it calculates the specificity of every rule, mapping them directly onto the corresponding HTML elements as inline styles.
* **`@css-inline/css-inline`**: A modern, exceptionally fast alternative to Juice. It is written in Rust and exposes Node.js bindings. If you are generating thousands of transactional emails a minute, this is the package to use.
* **`inline-css`**: A popular wrapper that uses Cheerio to traverse the DOM and apply styles. It abstracts away a lot of the heavy lifting of fetching remote stylesheets and mapping them to the DOM.

## Performance & Critical Path (Partial Inlining)

Sometimes you don't want to offlinize the whole page, but you *do* want to inline the specific assets required to render the top of the page instantly (improving the First Contentful Paint metric).

* **`critical`**: Extracts the "critical-path" CSS (the styling required for above-the-fold content) and inlines it directly into the `<head>`. The rest of the CSS is deferred until after the page loads.
* **`penthouse`**: The underlying engine that powers `critical` and many similar tools. It runs a headless browser, renders the page at various viewport sizes, and mathematically determines exactly which CSS rules apply to the visible screen.

## Asset-Specific Processors

If you are writing a custom build script and just need to linearize specific types of media manually, these focused packages do one thing well.

* **`base64-img`**: Provides a simple API to convert local files or remote image URLs into base64 data strings, making them ready to drop into an `<img>` `src` attribute or a CSS `background-image`.
* **`image-to-base64`**: A lightweight, dependency-free alternative focused purely on fetching an image and returning the raw base64 string.
* **`svgo`**: While primarily a compressor, SVGO is heavily used in linearization pipelines to strip XML cruft from SVGs so they can be safely embedded directly inline into the HTML DOM without bloating the file.
