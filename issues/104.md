To get 100% accurate vector screenshots (PDF or SVG) that capture the screen rendering exactly as you see it—without print layouts overriding colors, omitting backgrounds, or splitting your page awkwardly across standard paper margins—you have to break standard "print to PDF" conventions.
Here is exactly how to do it programmatically using modern browser engines.
1. Perfect "Infinite" or Paginated PDFs (Chromium Only)
Modern browser engines (Playwright, Puppeteer, Selenium) only support native PDF generation via Chromium (Headless). Firefox and WebKit do not expose a stable CDP (Chrome DevTools Protocol) endpoint for saving as PDF natively via automation wrappers.
To ensure it looks exactly like the screen and not a standard printed document, you must:
1. Emulate the screen media type (ignoring @media print CSS overrides).
2. Force -webkit-print-color-adjust: exact so CSS backgrounds are preserved.
3. Calculate the bounding box dynamically if you want an infinite/unpaginated canvas.
The Playwright Code (Python)
import asyncio
from playwright.async_api import async_playwright

async def capture_pdf_screenshot(url, output_path, infinite=True):
    async_playwright() as p:
        # PDF generation natively requires Chromium Headless
        browser = await p.chromium.launch(headless=True)
        page = await browser.new_page()
        
        # 1. Force the page to render in 'screen' mode instead of 'print'
        await page.emulate_media(media="screen")
        await page.goto(url, wait_until="networkidle")

        # Inject CSS to override default browser print margins/background behaviors
        await page.add_style_tag(content="""
            @page { margin: 0 !important; }
            body { -webkit-print-color-adjust: exact !important; print-color-adjust: exact !important; }
        """)

        if infinite:
            # 2. Get the exact scrollable height and width of the page
            dimensions = await page.evaluate("""() => {
                return {
                    width: Math.max(document.body.scrollWidth, document.documentElement.scrollWidth),
                    height: Math.max(document.body.scrollHeight, document.documentElement.scrollHeight)
                }
            }""")
            
            # Print as a single, perfectly scaled "infinite" canvas page
            await page.pdf(
                path=output_path,
                width=f"{dimensions['width']}px",
                height=f"{dimensions['height']}px",
                print_background=True,
                margin={"top": 0, "right": 0, "bottom": 0, "left": 0}
            )
        else:
            # Paginated format, but maintaining the screen rendering 
            await page.pdf(
                path=output_path,
                format="A4",
                print_background=True,
                margin={"top": 0, "right": 0, "bottom": 0, "left": 0}
            )

        await browser.close()

asyncio.run(capture_pdf_screenshot("https://example.com", "screenshot.pdf", infinite=True))

2. True "SVG Screenshots" (Chromium, WebKit, & Firefox)
Browsers do not have a native "Save page as SVG" function. If you try to snapshot a webpage to SVG, you cannot just change a file extension.
The programmatically valid way to achieve this across all engines is to wrap the DOM into an SVG <foreignObject>. Because it's pure text processing, you can extract the DOM, embed the stylesheets, and wrap it in an SVG string.
The Playwright Implementation (Cross-Browser)
This injects a lightweight bundle to serialize the DOM into an SVG data URI, maintaining exact styling.
import asyncio
from playwright.async_api import async_playwright

async def capture_svg_screenshot(url, output_path):
    async p as playwright:
        # Works perfectly across chromium, firefox, or webkit
        browser = await p.webkit.launch(headless=True) 
        page = await browser.new_page()
        await page.goto(url, wait_until="networkidle")

        # Use an in-browser evaluation to wrap the document into a vector SVG string
        svg_content = await page.evaluate("""() => {
            const width = Math.max(document.body.scrollWidth, document.documentElement.scrollWidth);
            const height = Math.max(document.body.scrollHeight, document.documentElement.scrollHeight);
            
            // XML-serialize the active DOM
            const serializer = new XMLSerializer();
            const xmlDoc = serializer.serializeToString(document.documentElement);
            
            // Inline all stylesheets to guarantee fidelity inside the SVG template
            let styles = '';
            for (const stylesheet of document.styleSheets) {
                try {
                    for (const rule of stylesheet.cssRules) {
                        styles += rule.cssText;
                    }
                } catch (e) {
                    // Catch CORS issues for external fonts/styles
                    console.log("Skipped some cross-origin styles: ", e);
                }
            }

            // Construct the raw SVG vector wrapper
            return `
            <svg xmlns="http://www.w3.org/2000/svg" width="${width}" height="${height}">
                <style>${styles}</style>
                <foreignObject width="100%" height="100%">
                    <div xmlns="http://www.w3.org/1999/xhtml">
                        ${xmlDoc}
                    </div>
                </foreignObject>
            </svg>
            `;
        }""")

        with open(output_path, "w", encoding="utf-8") as f:
            f.write(svg_content)
            
        await browser.close()

asyncio.run(capture_svg_screenshot("https://example.com", "screenshot.svg"))

Caveat for SVG: Embedded <foreignObject> items work perfectly when rendering the SVG inside a browser or advanced vector editors (like Illustrator). However, if you open it in basic image viewers, complex external fonts or images hidden behind security policies (CORS) might require you to explicitly base64-encode images into the SVG asset mapping first.
3. macOS Native: Direct PyObjC (WebKit)
If you are on macOS and want to bypass massive node modules or python binaries like Playwright, you can target the native macOS Cocoa WebKit wrapper (WKWebView) directly using PyObjC.
Under macOS, a WKWebView can output a WKPdfConfiguration directly.
import sys
from Cocoa import NSURL, NSRunLoop, NSDate
from WebKit import WKWebView, WKWebViewConfiguration, WKPdfConfiguration
from Foundation import NSObject

class WebKitPDFDelegate(NSObject):
    def init(self):
        self = super(WebKitPDFDelegate, self).init()
        self.completed = False
        return self

    def webView_didFinishNavigation_(self, webView, navigation):
        # Give the JS main thread an extra tick to settle layout execution
        config = WKPdfConfiguration.alloc().init()
        
        # This native method creates a mathematically true PDF representation of the full frame
        webView.createPDFWithConfiguration_completionHandler_(
            config, 
            self.handle_pdf_result
        )

    def handle_pdf_result(self, data, error):
        if error:
            print(f"Error creating vector layout: {error}")
        else:
            data.writeToFile_atomically_("macos_native_screenshot.pdf", True)
            print("Successfully exported absolute vector screenshot.")
        self.completed = True

def capture_native_macos_pdf(url_string):
    config = WKWebViewConfiguration.alloc().init()
    # Hidden view, completely independent of system rendering frames
    web_view = WKWebView.alloc().initWithFrame_configuration_(((0, 0), (1280, 800)), config)
    
    delegate = WebKitPDFDelegate.alloc().init()
    web_view.setNavigationDelegate_(delegate)
    
    url = NSURL.URLWithString_(url_string)
    web_view.loadRequest_(url)
    
    # Run loop block to sync asynchronous Objective-C callbacks in a procedural script
    while not delegate.completed:
        NSRunLoop.currentRunLoop().runMode_beforeDate_(
            "NSDefaultRunLoopMode", 
            NSDate.dateWithTimeIntervalSinceNow_(0.1)
        )

if __name__ == "__main__":
    capture_native_macos_pdf("https://example.com")

Summary of Best Tools
• For Infinite / Seamless PDFs: Chromium Headless via Playwright paired with custom dimension parsing is the industry gold standard.
• For Cross-Browser Vectors (SVG): The DOM foreignObject XML serialization trick works identically across Chromium, Firefox, and WebKit.
• For Zero-Dependency Mac Automation: PyObjC interfacing directly with native WKWebView delivers blazing fast results without spinning up isolated server binaries.


Here's a practical breakdown of how to programmatically capture **PDF or SVG "screenshots"** that faithfully replicate on-screen rendering (no print styles, no white background, no extra margins) across the three engines.

## Chromium — the most flexible option

Chromium (via Playwright, Puppeteer, or raw Chrome DevTools Protocol) is the only engine that natively exposes `Page.printToPDF`, which is what every PDF-generation library wraps under the hood. [nanx](https://nanx.me/blog/post/chromote-pdf-automation/)

Key flags to make the PDF match the screen exactly:

- Call `page.emulateMedia({ media: 'screen' })` so the page is rendered with screen CSS rather than `@media print`. [checklyhq](https://checklyhq.com/docs/learn/playwright/generating-pdfs)
- Set `printBackground: true` so backgrounds, gradients, and images are not stripped. [checklyhq](https://checklyhq.com/docs/learn/playwright/generating-pdfs)
- Inject `* { -webkit-print-color-adjust: exact; print-color-adjust: exact; }` to keep original colors. [stackoverflow](https://stackoverflow.com/questions/78346908/puppeteer-ignoring-background-color-property-in-generated-pdf)
- Set `margin: { top: 0, right: 0, bottom: 0, left: 0 }` to eliminate page margins. [docupotion](https://docupotion.com/blog/generate-pdfs-playwright)
- Use `preferCSSPageSize: true` together with a CSS `@page { size: <Wpx> <Hpx>; margin: 0 }` rule sized to `document.documentElement.scrollWidth/scrollHeight` to produce a single "infinite" page. [browserstack](https://www.browserstack.com/guide/playwright-pdf-html-generation)

Minimal Playwright (Python) example:

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page(viewport={"width": 1440, "height": 900})
    page.goto(url, wait_until="networkidle")
    page.emulate_media(media="screen")
    page.add_style_tag(content="""
        @page { margin: 0; size: auto; }
        html, body { background: transparent !important; }
        * { -webkit-print-color-adjust: exact !important; print-color-adjust: exact !important; }
    """)
    w, h = page.evaluate("[document.documentElement.scrollWidth, document.documentElement.scrollHeight]")
    page.pdf(
        path="out.pdf",
        width=f"{w}px", height=f"{h}px",
        print_background=True,
        prefer_css_page_size=True,
        margin={"top":"0","right":"0","bottom":"0","left":"0"},
    )
```

For paginated output, swap `width/height` for `format: "A4"` and let CSS `@page` control breaks. Note that Chromium PDFs always rasterize a background — to get a *transparent* PDF you must set `body { background: transparent }` and avoid `printBackground` painting a white canvas; in practice you get true transparency only by post-processing (e.g. `qpdf`/`mutool` to strip the white page box) because `printToPDF` always emits an opaque page. [docupotion](https://docupotion.com/blog/generate-pdfs-playwright)

## WebKit — only via native APIs

Playwright's WebKit binding does **not** implement `page.pdf()` — it's Chromium-only. To capture from WebKit you must drop down to native macOS APIs. [checklyhq](https://checklyhq.com/docs/learn/playwright/generating-pdfs)

With **PyObjC** driving `WKWebView`, use `createPDFWithConfiguration:completionHandler:` (the Swift `createPDF` method): [digitalbunker](https://digitalbunker.dev/how-to-create-pdf-from-wkwebview/)

```python
from WebKit import WKWebView, WKWebViewConfiguration, WKPDFConfiguration
from Foundation import NSURL, NSURLRequest, CGRect

wv = WKWebView.alloc().initWithFrame_configuration_(
        ((0,0),(1440,900)), WKWebViewConfiguration.alloc().init())
wv.loadRequest_(NSURLRequest.requestWithURL_(NSURL.URLWithString_(url)))
# …wait for didFinishNavigation via a delegate…

cfg = WKPDFConfiguration.alloc().init()
cfg.setRect_(((0,0),(wv.scrollView().contentSize().width,
                    wv.scrollView().contentSize().height)))  # full page → "infinite"
wv.createPDFWithConfiguration_completionHandler_(cfg,
        lambda data, err: data.writeToFile_atomically_("out.pdf", True))
```

`WKPDFConfiguration.rect` set to the full `scrollView.contentSize` produces a single non-paginated PDF that mirrors the screen rendering — no print CSS is applied, so transparency and exact colors are preserved natively. For pagination, slice the rect into viewport-sized chunks and concatenate. [digitalbunker](https://digitalbunker.dev/how-to-create-pdf-from-wkwebview/)

## Firefox — no native PDF API in automation

Neither Selenium nor Playwright Firefox supports headless PDF export; Gecko has no equivalent of `printToPDF` exposed to remote protocols. Practical options: [checklyhq](https://checklyhq.com/docs/learn/playwright/generating-pdfs)

- Use Selenium's `--print-to-pdf` via the WebDriver BiDi `browsingContext.print` command (Firefox 108+), but it always uses *print* media, with paginated output and configurable margins; setting `margin: {top:0,…}` and `shrinkToFit:false` gets you closest to screen rendering, but `@media screen` styles will not apply.
- Render to an oversize viewport and take a full-page **PNG** screenshot, then wrap it in a single-page PDF — the only way to get pixel-identical screen output from Firefox.

## SVG "screenshots"

No browser can export a live DOM to vector SVG directly; CDP, WebKit, and Gecko all rasterize for PDF/PNG. Workable approaches:

- **Embedded-raster SVG**: take a full-page PNG via Playwright `page.screenshot({ fullPage: true, omitBackground: true })` (the `omitBackground` flag gives true transparency on Chromium and WebKit) and wrap it as `<svg><image href="data:image/png;base64,…"/></svg>`. [playwright](https://playwright.dev/docs/api/class-page)
- **True vector SVG**: inject a library like `dom-to-svg` or `html-to-svg` into the page via `page.evaluate`, serialize the resulting `<svg>`, and write it out. This preserves text as text and shapes as paths but is imperfect for complex CSS (filters, transforms, canvas, video). [playwright](https://playwright.dev/docs/api/class-page)
- **PDF→SVG**: generate a Chromium PDF as above and convert with `mutool convert -O text=path -o out.svg in.pdf` or `pdf2svg`, which yields per-page vector SVGs that match the PDF exactly. [nanx](https://nanx.me/blog/post/chromote-pdf-automation/)
