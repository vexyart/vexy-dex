# 09 — Stage 2: Viewport Pagination Analysis

This is the most vexy-dex-specific logic and the reason "stupid pagination"
dies. No off-the-shelf library does it; we build it on Playwright. The job: at
the target stage size, decide where slides should start, snapping to semantic
boundaries rather than slicing mid-paragraph.

## The probe

Render the localized page in Chromium at the exact stage size ([05](05.md)) and
collect the geometry and tag of every candidate element:

```python
js = """
() => {
  const sel = 'section, article, h1, h2, h3, img, .card, [class*="hero"]';
  return Array.from(document.querySelectorAll(sel)).map(el => {
    const r = el.getBoundingClientRect();
    const cs = getComputedStyle(el);
    return {tag: el.tagName.toLowerCase(),
            top: r.top + scrollY, height: r.height,
            visible: cs.display !== 'none' && r.height > 0,
            text: (el.innerText || '').slice(0, 80)};
  });
}
"""
elements = page.evaluate(js)
```

Use the same `width×height` viewport the exporters will use, so the analysis and
the render agree.

## Break algorithm

Reference logic (adapted from gemi's `_calculate_breakpoints`), producing a
sorted, deduplicated list of `Break` ([03](03.md)):

```python
def plan_breaks(elements, stage_h, tol=50):
    els = sorted((e for e in elements if e["visible"]), key=lambda e: e["top"])
    breaks, cursor = [], 0.0
    for e in els:
        h = e["height"]
        if h > stage_h:                       # over-tall block: split into screens
            for k in range(1, round(h / stage_h)):
                breaks.append(Break(e["top"] + k * stage_h, "overflow", 0.6))
            cursor = e["top"] + h
        elif e["top"] > cursor + stage_h - tol:   # would overflow the stage
            breaks.append(Break(e["top"], "overflow", 0.8))
            cursor = e["top"]
        elif e["tag"] in ("h1", "h2", "section", "article") \
                and (e["top"] - cursor) > stage_h * 0.4:   # semantic start
            breaks.append(Break(e["top"], e["tag"], 1.0))
            cursor = e["top"]
    return SlidePlan(stage_w, stage_h, dedupe_sorted(breaks))
```

## Rules in plain words

1. **Semantic markers win.** A `<section>`, `<article>`, `<h1>`, or `<h2>`
   begins a new slide when the current slide already has enough content
   (> 40% of stage height) — so we don't emit near-empty slides.
2. **Never overflow silently.** If the next element would push past the stage,
   break before it.
3. **Split giants.** A block taller than the stage is divided into the minimum
   number of stage-height screens, so nothing is cut off.
4. **Respect a tolerance.** Don't insert a break for a few stray pixels; `tol`
   absorbs sub-pixel and rounding noise.

## Output and hand-off

`SlidePlan` rides alongside `PageDoc` into the importer ([11](11.md)). For
CSS-paged engines, breaks become `break-before`/`break-after` rules
([15](15.md)); for the reveal path they become `<section>` boundaries; for
Playwright's continuous `page.pdf` they inform a forced-break stylesheet.

## When heuristics aren't enough

For pages with no semantic structure (a single `<div>` soup), the heuristic
falls back to pure screen-count slicing, and the optional vision model
([10](10.md)) can refine breaks. The vision step *adjusts* this plan; it never
replaces the deterministic baseline.
