# 22 — Error Handling, Logging & Observability

vexy-dexypy orchestrates flaky externals — networks, browsers, Node CLIs, optional
model servers. Partial failure is a normal third outcome, not an exception.
Design the recovery path first ([01](01.md), and the global engineering rules).

## The partial-failure rule

A failed strategy degrades to a warning; the run continues. The orchestrator
collects a `DeckResult` per strategy ([03](03.md)) — `ok=True` with files, or
`ok=False` with a human message — and prints a summary:

```
vexy-dexypy build https://www.vexy.art/lines/
✓ playwright   11 slides   out/lines/playwright/
✓ reveal        9 slides   out/lines/reveal/
✗ vivliostyle  failed: `vivliostyle` not found on PATH — `npm i -g @vivliostyle/cli`
2/3 strategies succeeded.
```

Exit `0` if ≥1 strategy succeeded, `2` if all failed, `1` for usage errors
before work starts ([04](04.md)).

## Error taxonomy

Typed errors, narrow and at boundaries (parse-don't-validate):

- `ReadError` — fetch/localize failed (Stage 1). Often fatal to the run (nothing
  to render) → exit `1`.
- `ImportError`/`NormalizeError` — a normalizer choked; fall back to the generic
  importer ([14](14.md)) before giving up.
- `ExportError` — one engine failed; isolated to its strategy.
- `WriteError` — splitting/SVG failed; isolated to its strategy.
- `VisionError` — model unavailable/garbage; log and proceed with the heuristic
  plan ([10](10.md)).

Errors carry context (URL, strategy, subprocess stderr) so the message tells the
user what failed and how to fix it. Error messages are UX.

## Retries

Network reads get one retry with exponential backoff + jitter, then fail
([06](06.md)). Renders are not retried — a deterministic engine failing twice
fails the same way. No retry framework; a small helper (anti-bloat, [01](01.md)).

## Logging

`loguru`, always available, `--verbose` flips INFO→DEBUG ([04](04.md)).

- INFO: stage transitions, strategy outcomes, slide counts.
- DEBUG: fingerprint matches + scores, break offsets and reasons, subprocess
  command lines, cache hits/misses, timings.
- WARNING: skipped strategies, missing assets/fonts, vision fallback.

Structured fields (`strategy=`, `slug=`, `stage=`) make per-strategy logs
greppable. This is the observability ceiling — no metrics/tracing stack
(anti-bloat).

## Debuggability

JSON sidecars in `_meta/` ([03](03.md), [21](21.md)) capture every
intermediate, and the per-stage CLI verbs ([04](04.md)) replay any stage from a
sidecar without re-fetching. Most bugs are reproduced by reading
`_meta/slideplan.json` and re-running `render`/`split` — no debugger attached to
a subprocess needed.
