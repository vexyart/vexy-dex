# 13 — Stage 3: MkDocs Material Importer

MkDocs Material pages are clean, semantic, and stable — the team is in
maintenance mode and the `md-` prefixed DOM is unlikely to churn. The importer
extracts the content column and splits it by heading.

## Detection

`detect` fires on `meta[generator]="mkdocs-material 9.x"`, `md-content`,
`md-typeset`, `md-nav`, or `data-md-component` ([08](08.md)).

## Transform

1. **Isolate content.** Keep `article.md-content__inner` (the `md-typeset`
   content). This is the slide source.
2. **Drop chrome.** Decompose `md-sidebar`, `md-header`, `md-footer`,
   `md-search`, `md-nav`, `.md-source-file`, `.md-content__button`, and the
   table-of-contents drawer.
3. **Split by heading.** Each `<h1>`/`<h2>` starts a new slide; its body runs
   until the next heading of the same level. If a resulting section exceeds the
   stage height ([09](09.md)), split further at `<h3>` boundaries, then by
   screen-count as a last resort.
4. **Wrap.** Emit the canonical `.reveal > .slides > section` structure
   ([11](11.md)). Tag background as `slide-light-bg` (docs are light by default;
   honour the page's palette if a dark theme is detected).

```python
class MkdocsImporter:
    name = "mkdocs-material"
    def detect(self, page): ...
    def transform(self, page, plan):
        soup = BeautifulSoup(page.html_path.read_text(), "lxml")
        drop_chrome(soup, ["md-sidebar", "md-header", "md-footer",
                           "md-search", "md-nav"])
        content = soup.select_one("article.md-content__inner") or soup.body
        sections = split_by_heading(content, levels=("h1", "h2"),
                                    max_h=plan.stage_h, fallback="h3")
        return write_normalized(page, wrap_reveal(sections))
```

## Code blocks and tables

MkDocs content carries syntax-highlighted code fences and tables that must
survive intact — they are why a documentation page becomes a useful deck. Do not
strip `<pre>`/`<code>`/`<table>`; preserve their classes so the highlight CSS
(localized in [07](07.md)) still applies. Vivliostyle ([18](18.md))
renders these cleanly; this is why it's the recommended strategy for MkDocs.

## Why Vivliostyle first

MkDocs HTML is declarative and JS-free, so the CSS paged engine produces
smaller, sharper output than Chromium screenshotting. The classifier recommends
it first in the strategy order ([05](05.md), [08](08.md)); Playwright remains
available as a fallback.

## Reference target

`blog.fontlab.com` (an MkDocs Material site) is the integration benchmark
([23](23.md)). A faithful, readable deck from it — code blocks intact, no
sidebar bleed — is the bar this importer must clear.
