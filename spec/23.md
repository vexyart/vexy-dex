# 23 — Testing Strategy & Functional Examples

Untested is broken. Every function gets at least one test; the pipeline gets
runnable end-to-end examples that double as tests. Target ≥80% coverage on the
core (excluding thin subprocess wrappers, which are covered by smoke runs).

## Test tiers

- **Unit** — pure functions: `classify` ([08](08.md)), `plan_breaks`
  ([09](09.md)), `split_by_heading`/`luminance`/`wrap_reveal` ([11](11.md)),
  the config parser ([05](05.md)), PDF split ([20](20.md)).
- **Edge** — empty page, no headings, single giant element, malformed HTML,
  missing assets, zero-height nodes, non-ASCII titles, a page already in reveal
  form (idempotency).
- **Error** — network off (`ReadError`), engine binary missing
  (`available()==False`), subprocess timeout, vision server down → heuristic
  fallback, corrupt PDF into the splitter.
- **Integration** — fixed local HTML fixtures through the whole pipeline for one
  strategy, asserting slide counts and file layout.
- **Smoke** — `vexy-dexypy build <fixture>` exits `0` and writes ≥1 deck.

Naming: `test_<func>_when_<condition>_then_<result>`, with assertion messages.

## Fixtures, not the live web

Tests must run offline and deterministically. Vendor small, license-clear HTML
samples under `tests/fixtures/`:

- `webflow_sample/` — a sectioned Webflow export ([12](12.md)).
- `mkdocs_sample/` — an MkDocs Material page with code blocks ([13](13.md)).
- `generic_article/` — a plain semantic article ([14](14.md)).
- `divsoup/` — an unstructured page to exercise screen-count fallback
  ([09](09.md)).

Never fetch from `vexy.art`/`fontlab.com` in CI — those are *manual* acceptance
targets, run locally against the staged reference pages.

## Golden output

For the pagination planner and importers, store golden `SlidePlan`/normalized-
HTML snapshots and diff against them. A planner change that moves breaks must
update goldens consciously — that's the review signal.

## Engine tests

The four exporters are thin subprocess/library wrappers. Test:

- `available()` logic (mock `shutil.which`).
- that `export` invokes the engine with the right stage size and output path
  (mock `subprocess.run`).
- one real smoke render per engine that is *installed* in the dev/CI image;
  skip (don't fail) when an engine is absent — engines are optional ([05](05.md)).

## `examples/` as living docs

An `examples/` folder holds runnable scripts demonstrating real usage
(single-strategy build, all-strategies build, split-only, vision-on). They are
referenced from the README ([../README.md]) and exercised in CI against the
fixtures — documentation that can't rot because it runs.

## Tooling

Per the project standards: `uvx hatch test`, `ruff`/`autoflake`/`pyupgrade` on
edit, `mypy` on the typed core, and a `./test.sh` that runs unit + integration +
the `examples/` smoke set.
