# 05 — Configuration, Profiles & Strategy Selection

Configuration stays minimal (anti-bloat, [01](01.md)). Most runs need no config
file at all — flags and defaults suffice. A TOML file exists for users who want
to pin a house style.

## Precedence

```
CLI flags  >  ./vexy-dexypy.toml  >  ~/.config/vexy-dexypy/config.toml  >  built-in defaults
```

Resolution happens once at startup into a frozen `Settings` object passed down
the pipeline. No stage reads global state.

## The config file

```toml
# vexy-dexypy.toml
[output]
dir = "out"
svg = false

[stage]
aspect = "16:9"          # or "4:3", "A4-landscape"
size = "1920x1080"       # overrides aspect when present

[strategies]
enabled = ["playwright", "vivliostyle", "reveal"]  # or "all"

[vision]
enabled = false
model = "minicpm-v-4.6"   # see chapter 10
endpoint = "http://localhost:11434"   # Ollama default

[engines]
prince_path = ""          # set to enable the opt-in Prince strategy (18)
node_bin = "node"         # for Vivliostyle subprocesses
```

## Aspect & size profiles

A profile resolves to a concrete `(stage_w, stage_h)` used everywhere — the
viewport in [09](09.md), the `@page size` in [15](15.md), the `page.pdf` size in
[17](17.md).

- `16:9` → `1920×1080` (default)
- `4:3` → `1440×1080`
- `A4-landscape` → `1123×794` (at 96dpi) for documentation-style decks
- `--size WxH` → arbitrary, overrides the named profile

Defining the stage in one place is what stops "stupid pagination" (research
consensus): every engine and the analyzer share the exact same numbers.

## Strategy selection

- `enabled = "all"` runs every exporter discovered via entry points
  ([16](16.md)) whose runtime dependencies resolve. A strategy whose binary is
  missing (e.g. no `node`) is skipped with a one-line notice, not an error.
- An explicit list runs exactly those, in order, and errors loudly if a named
  strategy is unknown (usage error, exit `1`, [04](04.md)).
- The classifier ([08](08.md)) may *recommend* a strategy order (Webflow →
  Playwright/reveal first; MkDocs → Vivliostyle first), but never
  removes a user-requested strategy.

## Validation

`Settings` is parsed at the boundary: unknown keys warn, malformed
`size`/`aspect` fail fast with a message showing the accepted forms. No
elaborate config-validation framework — a few explicit checks (anti-bloat).
