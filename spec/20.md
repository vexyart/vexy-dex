# 20 — Stage 6: Writers

Writers are purely technical ([01](01.md)): take a strategy's multi-page PDF and
produce named single-page PDFs, optional SVGs, and a preview index. Output goes
into the strategy's folder; nothing here is creative.

## Output layout

```
out/<slug>/
  _meta/                      # JSON sidecars (PageDoc, SlidePlan, run summary)
  playwright/
    01-slide.pdf  02-slide.pdf  …
    01-slide.svg  02-slide.svg  …      # if --svg
    index.html                          # reveal preview
  vivliostyle/  …
  reveal/       …
```

Per-slide files are zero-padded and ordered (`01-`, `02-`, …) so a directory
listing is the slide order. An optional title slug from the slide's `h1/h2` can
suffix the name (`01-hero.pdf`) when detected.

## PDF splitting

Default to `pypdf` — pure Python, BSD, vendorable, fine for a permissively
licensed tool:

```python
from pypdf import PdfReader, PdfWriter

def split(pdf_path, out_dir, prefix=""):
    reader = PdfReader(pdf_path)
    paths = []
    for i, page in enumerate(reader.pages, 1):
        w = PdfWriter(); w.add_page(page)
        p = out_dir / f"{i:02d}-{prefix or 'slide'}.pdf"
        w.write(p); paths.append(p)
    return paths
```

- Use **`pikepdf`** (MPL-2.0, qpdf) when a PDF is damaged or must preserve
  XObjects/OCGs (e.g. reveal backgrounds).
- **Do not** reach for `PyMuPDF` unless the project licenses AGPL/commercial —
  it's fastest but AGPL ([24](24.md)).

## SVG export

There are two routes to a faithful per-slide SVG (issue 104). They differ in
*when* the vectorisation happens, and so in what they preserve.

### Strategy A — PDF → SVG (default)

Convert each faithful slide PDF ([17](17.md)) with **`vexy-pdfsvgpy`** (the sibling
project), which wraps `pdftocairo` (poppler) with a `mutool convert` fallback.
vexy-dexypy does not implement PDF→SVG itself:

```python
from vexy_pdfsvgpy import pdf_to_svg
for i, slide in enumerate(slide_pdfs, 1):
    pdf_to_svg(slide, out_dir / f"{i:02d}-slide.svg", page=1)
```

The SVG is exactly the PDF re-expressed as vectors, so it inherits the PDF's
faithfulness (screen media, real backgrounds, exact stage size) and stays in lock
step with the PDF a user might pick instead. This is the default because the PDF
is already the product; the SVG must not diverge from it. Avoid Inkscape (breaks
ligatures) and cairosvg/svglib (wrong direction; on vexy-pdfsvgpy's reject list).

### Strategy B — DOM → SVG (optional, browser-side)

Capture the SVG *in the browser* before any PDF exists, by serialising the live
DOM into an `<svg>` — either `<foreignObject>`-wrapped XHTML with inlined
stylesheets, or a true-vector pass (`dom-to-svg`) that emits text as text and
boxes as paths. This is the only route that works on WebKit/Firefox (which have no
automation PDF API) and can yield genuinely transparent backgrounds, but it is
imperfect for complex CSS (filters, transforms, `canvas`, `video`) and can drift
from the Chromium PDF. Treat it as an opt-in alternative engine, not the default;
when used, PDF is produced *from* the SVG (rsvg/resvg) so the pair stays
consistent. Foreign-object SVGs also need images base64-inlined to render outside
a browser. Deferred — see [`../TODO.md`](../TODO.md).

## Reveal preview index

Emit an `index.html` per strategy: one `<section>` per slide containing the
slide's SVG (or PDF embed), inside the reveal chassis sized to the stage. This
gives the user a scrollable, navigable preview to choose from:

```python
def build_reveal_preview(svgs, out, w, h):
    secs = "\n".join(
        f'<section><img src="{p.name}" '
        f'style="width:100%;height:100%;object-fit:contain"></section>'
        for p in svgs)
    out.write_text(REVEAL_TEMPLATE.format(sections=secs, w=w, h=h))
```

When SVGs aren't generated, embed the per-slide PDFs (`<embed type=application/pdf>`).

## DeckResult

The writer returns a `DeckResult` ([03](03.md)) listing produced files, `ok`,
and any `error`. The orchestrator collects these across strategies for the run
summary ([22](22.md)). A writer failure on one strategy is isolated like any
other ([02](02.md)).
