# 03 — Data Model & Intermediate Representation

Stages talk only through typed artifacts. Following "parse, don't validate,"
raw input becomes a typed object at the boundary, and its existence proves
validity. Use dataclasses (or Pydantic where external/serialized) at I/O edges.

## Core types

```python
from dataclasses import dataclass, field
from pathlib import Path
from enum import Enum

class SourceKind(Enum):
    URL = "url"
    FILE = "file"

@dataclass(frozen=True)
class Source:
    """What the user asked us to convert."""
    raw: str                 # the URL or path as given
    kind: SourceKind
    slug: str                # filesystem-safe identifier derived from raw

@dataclass
class PageDoc:
    """A localized, parseable page. The spine of the pipeline."""
    source: Source
    html_path: Path          # local index.html (assets rewritten to relative)
    asset_dir: Path          # localized assets live here
    framework: str = "generic"   # set by the classifier (08)
    meta: dict = field(default_factory=dict)  # title, generator, etc.
    content_hash: str = ""   # of html + assets; cache key (21)

@dataclass(frozen=True)
class Break:
    """One pagination boundary."""
    y: float                 # vertical offset on the rendered stage, px
    reason: str              # "section" | "h2" | "overflow" | "vision"
    confidence: float = 1.0

@dataclass
class SlidePlan:
    """Where slides should start, decided by the pre-importer (09/10)."""
    stage_w: int             # e.g. 1920
    stage_h: int             # e.g. 1080
    breaks: list[Break]      # sorted, deduplicated
    notes: dict = field(default_factory=dict)

@dataclass(frozen=True)
class Strategy:
    """A named rendering route — a (chassis × engine) pair (15, 16)."""
    name: str                # "playwright" | "vivliostyle" | "reveal" | "prince" | "impress" | "marp"
    exporter: str            # entry-point name of the exporter plugin
    chassis: str = "paged"   # "paged" | "reveal" | "impress" | "marp" (15)

@dataclass
class RenderJob:
    """Engine-ready input for one strategy (built by the pre-exporter, 15)."""
    page: PageDoc
    plan: SlidePlan
    strategy: Strategy
    html_path: Path          # possibly transformed (reveal-wrapped, css-injected)
    extra_css: list[Path] = field(default_factory=list)

@dataclass
class DeckResult:
    """What a writer produces for one strategy (20)."""
    strategy: Strategy
    out_dir: Path
    slide_pdfs: list[Path]
    slide_svgs: list[Path] = field(default_factory=list)
    index_html: Path | None = None
    ok: bool = True
    error: str | None = None
```

## Invariants

- `PageDoc.html_path` always points at a file whose asset references resolve
  locally — the offline guarantee ([07](07.md)). A reader that can't satisfy
  this raises rather than returning a half-localized doc.
- `SlidePlan.breaks` is sorted ascending by `y`, deduplicated within a
  tolerance, and never empty (a one-slide plan has zero interior breaks but a
  defined stage).
- `Strategy.name` is unique within a run and is the output sub-folder name.
- `DeckResult.ok == False` carries a human-readable `error` and an empty
  `slide_pdfs`; the orchestrator collects these for the run summary
  ([22](22.md)).

## Why a shared IR

The IR is what lets a strategy fail in isolation, lets the cache key on
`content_hash`, and lets a new exporter consume `RenderJob` without knowing how
the page was fetched or classified. Keep it small; resist adding engine-specific
fields — those belong in the plugin, passed via `RenderJob.extra_css` or a
strategy-scoped options dict, not on the shared types.

## Serialization

`PageDoc`, `SlidePlan`, and `DeckResult` serialize to JSON sidecars in the
output tree (`<slug>/_meta/`) so the per-stage CLI verbs ([04](04.md)) can run
independently and so runs are debuggable without re-fetching.
