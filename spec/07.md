# 07 — Asset Localization & Offline Bundling

This chapter applies to **`localize` fetch mode** ([06](06.md)). The default
`live` mode deliberately skips localization — it keeps assets online and renders
them in the browser (issue 103), trading reproducibility for fidelity.

The offline guarantee (in `localize` mode): after Stage 1, every reference in
`PageDoc.html_path` resolves to a local file and no downstream engine touches the
network. This chapter specifies the asset localization tier and offlinization
tools. (In `live` mode there is no such guarantee — downstream stages load assets
from the live origin via the injected `<base href>`.)

## What must be localized

- `<link rel=stylesheet>`, `<script src>`, `<img src>` and `srcset`, `<source>`.
- CSS-referenced assets: `@import` chains, `url(...)` backgrounds, `@font-face`
  web fonts.
- Protocol-relative (`//cdn…`) and absolute URLs rewritten to relative local
  paths.

## Three localization & "offlinization" tiers

`vexy-dexypy` selects a tier by page kind, or allows the user to force a specific
method:

1. **Custom Python Downloader (baseline).** A thread-pool walker in `vexy-dexypy`
   scans the DOM, fetches tag-referenced assets into `asset_dir`, and rewrites the URLs.
   CSS `url()` strings are parsed and recursively localized.
2. **`pywebcopy` / `node-website-scraper` (static pages).** For static pages, the pipeline
   mirrors the site structure and rewrites paths in a single pass.
3. **JS-based Offlinization (dynamic pages).** Shuffled to `vexy-dexyjs` executing in the
   browser/Node context. `vexy-dexyjs` coordinates specialized libraries to inline or bundle
   assets:
   - **Single-file page archivers:** For compiling full dynamic pages (DOM + CSS + fonts + JS)
     into a single HTML file, `vexy-dexyjs` uses `single-file-cli` (via Puppeteer/Playwright),
     `monolith` (Rust-based, npm wrapper), `nodeSavePageWE`, or `inliner` / `tauri-inliner`.
     This resolves network requests, fully hydrates the page, and produces one self-contained file.
   - **CSS inliners:** When preparing pages for slide email output or embedding where stylesheets
     are blocked, it runs `juice` / `juice2`, `inline-css`, or the high-performance `@css-inline/css-inline`
     (Rust backend with Node bindings) to inline `<style>` and `<link>` rules directly into
     HTML element `style=""` attributes.
   - **Build-time Single-file output:** For exporting decks or slide apps as single-file web apps,
     it uses `vite-plugin-singlefile` or `html-bundle` to inline JS/CSS bundles.

## Path sanitation

- Hash or namespace long/duplicate filenames to avoid collisions and path
  traversal.
- Keep the asset tree under `asset_dir`; never write outside `out/<slug>/`.
- Preserve enough of the original path to keep relative `@font-face` and
  `srcset` resolution intact.

## Fonts matter for fidelity

Pagination depends on font metrics. If a web font fails to localize, the engine
substitutes and line-breaks shift, breaking the `SlidePlan` ([09](09.md)).
Treat a failed `@font-face` download as a loud warning, and prefer the
`single-file-cli` or `monolith` tier for font-heavy designs.

## Content hash

After localization, compute `PageDoc.content_hash` over the normalized HTML plus
a manifest of asset bytes. This is the cache key ([21](21.md)) and the
determinism anchor ([02](02.md)).
