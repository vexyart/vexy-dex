# 12 — Stage 3: Webflow Importer

Webflow exports are already a stack of full-width `<section>`s with consistent
class names — the friendliest input vexy-dex gets. The transform is solved: it
lives in `private/webflow2reveal/py/src/webflow2reveal/compiler.py` (~31 KB, one
file). **Copy and adapt that code into vexy-dex** — do not reinvent it, and do
not depend on the `webflow2reveal` package.

`webflow2reveal` is a legacy one-trick pony (the author's own repo). vexy-dex
supersedes it: this importer becomes the canonical home of the Webflow→slides
logic, generalized to vexy-dex's pipeline (the shared `SlidePlan`, layout
vocabulary, and configurable stage). Once this importer reaches parity, the
old `webflow2reveal` Python package is slated for removal ([24](24.md)). Because
it is the author's own code, there is no licence or attribution constraint on
copying it.

## Detection

`detect` fires on `data-wf-page`, `[data-w-id]`, `html.w-mod-js`, or `w-*`
classes / `webflow.js` ([08](08.md)). High confidence when several co-occur.

## The five-step transform (ported verbatim)

1. **Resolve colours.** Scan inline and linked stylesheets into a
   `class → background-colour` map. This recovers the page's own palette so
   slides keep their intended look offline.
2. **Select slides.** Each top-level `<section>` becomes a slide *unless* its
   classes/id mark it as nav, footer, menu, header, or banner — those are
   dropped. Use `drop_chrome` ([11](11.md)) with Webflow's chrome selectors.
3. **Normalize the DOM.** Rewrite each slide into the layout vocabulary
   ([11](11.md)): `slide-split-layout`, `slide-column`, `slide-text-container`,
   `slide-image-cover`, `slide-badge`. Flatten Webflow's nested transition
   wrappers and extract content from slider/interaction containers.
4. **Classify backgrounds.** Compute perceptual luminance of each slide's
   resolved background; set `data-background-color` and tag the slide
   `slide-light-bg` or `slide-dark-bg` so themes pick correct text colour.
5. **Inject Reveal.js 5.1.** Wrap in the `.reveal > .slides` chassis and attach a
   bundled stylesheet that sizes everything to the stage and hides residual
   Webflow chrome.

## Copy, adapt, supersede

The entire transform is `webflow2reveal/py/src/webflow2reveal/compiler.py` — one
~31 KB module. Copy it to `vexy_dex/importers/webflow/compiler.py` and adapt:

- Replace its hard-coded 1440×900 stage with vexy-dex's configured stage
  ([05](05.md)).
- Emit the shared layout vocabulary and reveal chassis via `vexy_dex.dom`
  helpers ([11](11.md)) rather than its private ones, so Webflow slides match
  every other importer's output.
- Reconcile with the `SlidePlan` ([09](09.md)) instead of assuming one section
  per slide.
- Drop the URL-fetching and dev-server bits — fetching is Stage 1 ([06](06.md)).

This is a deliberate replacement, not a dependency. `webflow2reveal` is a legacy
one-trick pony kept only as the reference until parity; it is then removed
([24](24.md)). It is the author's own code, so there is no licence concern —
nothing to record in `DEPENDENCIES.md` for it.

## Stage size

`webflow2reveal` targets a 1440×900 stage by default. vexy-dex overrides this
with the configured stage ([05](05.md)) via `Reveal.initialize({width, height})`
and the injected `@page`/sizing CSS ([15](15.md)) so all strategies share one
geometry.

## Interaction with the SlidePlan

Webflow's explicit sections usually match the plan; where a section is taller
than the stage, the plan's `overflow` breaks ([09](09.md)) split it into
sub-slides. Where a section is tiny, adjacent sections may merge — the importer
reconciles, preferring Webflow's authored boundaries.
