# 12 — Stage 3: Webflow Importer

Webflow exports are already a stack of full-width `<section>`s with consistent
class names — the friendliest input `vexy-dexypy` gets. The transform lives
primarily as a JavaScript library in the companion package `vexy-dexyjs`
(porting and generalizing the JS compiler from `./private/webflow2reveal/js/`
and `webflow2revealjs` on NPM).

`vexy-dexypy` supersedes the legacy `webflow2reveal` Python package. DOM restructuring
is carried out in the browser by injecting and invoking `vexy-dexyjs`. Once the JS-based
importer reaches parity, the legacy `webflow2reveal` package is scheduled for removal
([24](24.md)).

## Detection

`detect` fires on `data-wf-page`, `[data-w-id]`, `html.w-mod-js`, or `w-*`
classes / `webflow.js` ([08](08.md)). High confidence when several co-occur.

## The five-step transform (executed in-browser JS)

1. **Resolve colours.** Scan inline and linked stylesheets into a
   `class → background-colour` map. This recovers the page's own palette so
   slides keep their intended look offline.
2. **Select slides.** Each top-level `<section>` becomes a slide *unless* its
   classes/id mark it as nav, footer, menu, header, or banner — those are
   dropped.
3. **Normalize the DOM.** Rewrite each slide into the layout vocabulary
   ([11](11.md)): `slide-split-layout`, `slide-column`, `slide-text-container`,
   `slide-image-cover`, `slide-badge`. Flatten Webflow's nested transition
   wrappers and extract content from slider/interaction containers.
4. **Classify backgrounds.** Compute perceptual luminance of each slide's
   resolved background; set `data-background-color` and tag the slide
   `slide-light-bg` or `slide-dark-bg` so themes pick correct text colour.
5. **Inject Reveal.js 5.1.** Wrap in the `.reveal > .slides` chassis and attach a
   bundled stylesheet that sizes everything to the stage and hides residual
   Webflow chrome.

```python
class WebflowImporter:
    name = "webflow"
    def detect(self, page): ...
    def transform(self, page, plan):
        # Python bridge invokes vexy-dexyjs in the browser context
        html = run_js_in_browser(page, "webflow", plan)
        return write_normalized(page, html)
```

## Stage size

`webflow2reveal` targets a 1440×900 stage by default. `vexy-dexypy` overrides this
with the configured stage ([05](05.md)) via `Reveal.initialize({width, height})`
and the injected `@page`/sizing CSS ([15](15.md)) so all strategies share one
geometry.

## Interaction with the SlidePlan

Webflow's explicit sections usually match the plan; where a section is taller
than the stage, the plan's `overflow` breaks ([09](09.md)) split it into
sub-slides. Where a section is tiny, adjacent sections may merge — the importer
reconciles, preferring Webflow's authored boundaries.
