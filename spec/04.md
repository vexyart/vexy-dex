# 04 — Command-Line Interface (Fire)

vexy-dex exposes its pipeline through [Python Fire](https://github.com/google/python-fire)
(Apache-2.0). Fire maps a class to a CLI with no boilerplate: methods become
subcommands, type-hinted parameters become flags.

## The command surface

```python
import fire

class VexyDex:
    def build(self, url: str, out: str = "out", aspect: str = "16:9",
              size: str = "1920x1080", strategies: str = "all",
              svg: bool = False, vision: bool = False, verbose: bool = False):
        """Run the whole pipeline: fetch → analyze → normalize → render → split."""

    def read(self, url: str, out: str = "out"):
        """Stage 1 only: fetch and localize. Emits a PageDoc sidecar."""

    def analyze(self, page: str, size: str = "1920x1080", vision: bool = False):
        """Stage 2 only: classify + plan breaks on an existing PageDoc."""

    def render(self, page: str, strategy: str, out: str = "out",
               size: str = "1920x1080"):
        """Stages 3–5 for one strategy: normalize → export to one PDF."""

    def split(self, pdf: str, out: str = ".", svg: bool = False, prefix: str = ""):
        """Stage 6 only: split a PDF into named per-slide files."""

def main():
    fire.Fire(VexyDex)
```

`build` is the headline command; the others expose single stages for debugging
and re-runs, consuming the JSON sidecars from [03](03.md).

## Flags

- `--out PATH` — output root. Layout: `out/<slug>/<strategy>/NN-*.pdf` plus
  `out/<slug>/_meta/*.json` ([20](20.md)).
- `--aspect 16:9 | 4:3 | A4` and `--size WxH` — target stage; `--size` wins if
  both given ([05](05.md)).
- `--strategies all | playwright,weasyprint,…` — which exporters to run
  ([16](16.md)). `all` = every discovered exporter whose dependencies resolve.
- `--svg` — also emit SVGs via `vexy-pdfsvgpy` ([20](20.md)).
- `--vision` — enable the optional MiniCPM-V pre-importer ([10](10.md)).
- `--verbose` — DEBUG-level `loguru` output ([22](22.md)).

## Usage

```bash
# Everything, every strategy, default 16:9
vexy-dex build https://www.vexy.art/lines/

# Two strategies, 4:3, with SVGs
vexy-dex build https://blog.fontlab.com/ --strategies weasyprint,playwright \
    --aspect 4:3 --svg

# Re-run just the split step on an existing PDF
vexy-dex split out/lines/playwright/_combined.pdf --out out/lines/playwright --svg
```

## The `--` caveat

Fire treats tokens after a positional argument as flags. When a flag value could
be read as a positional, separate with `--`. Document this in `--help` examples;
it catches every newcomer (noted in [`../RESEARCH.md`](../RESEARCH.md)).

## Exit codes

- `0` — at least one strategy produced a valid deck.
- `1` — usage error (bad flag, unreadable input) — fail fast, before any work.
- `2` — every strategy failed (the run ran but produced nothing) ([22](22.md)).

A partial success (some strategies failed) still exits `0` and prints a summary
table of per-strategy outcomes. Errors are user experience: each message names
the strategy, the cause, and the fix.

## Help and discovery

Fire auto-generates `--help`. The `build` docstring lists the strategies
discovered at runtime so users see what their install actually supports (a
missing Node means no Vivliostyle/DeckTape — say so plainly).
