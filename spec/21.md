# 21 — Orchestration, Concurrency & Caching

The orchestrator wires the six stages, fans out across strategies, bounds the
heavy resources, and caches expensive work. It owns control flow; stages stay
ignorant of each other ([02](02.md)).

## The fan-out graph

```
read ──► classify+plan ──► import (once) ──┬─► pre-export ─► export ─► write   (playwright)
                                           ├─► pre-export ─► export ─► write   (weasyprint)
                                           ├─► pre-export ─► export ─► write   (vivliostyle)
                                           └─► pre-export ─► export ─► write   (decktape)
```

Stages 1–3 run once per page; stages 4–6 run per strategy, concurrently and
independently.

## Structured concurrency

Use **`anyio`** task groups (runs on asyncio or trio) so children never outlive
the parent scope — no orphaned subprocesses. Per the global engineering rules,
unbounded `spawn` is the new `goto`; every strategy task lives inside one group
and is cancellable.

```python
async with anyio.create_task_group() as tg:
    for strat in strategies:
        tg.start_soon(run_strategy, normalized, plan, strat, limiter)
```

## Bounding the browser pool

Chromium is heavy (~200 MB, 1–3 s launch). Cap concurrent browser-class
exporters with an `anyio.CapacityLimiter` sized to the machine (default
`min(cpu, 3)`). Pure-Python WeasyPrint runs outside that limit. Keep a warm
browser/context for reuse across Playwright exports and the pagination probe
([09](09.md), [17](17.md)) rather than relaunching per slide.

## Timeouts and cancellation

Every subprocess and browser op carries a timeout ([16](16.md)). A doomed
strategy is cancelled and recorded as a failed `DeckResult` ([22](22.md)); its
cancellation never propagates to siblings. Deadlines are passed down, not
stacked per hop.

## Content-addressed cache

Cache keys on `PageDoc.content_hash` ([07](07.md)) plus strategy + relevant
settings:

- **Localized page** — keyed by source + fetch mode; skip re-fetch on re-run.
- **SlidePlan** — keyed by `content_hash + stage`; skip re-analysis.
- **Vision plan** — keyed by `screenshot_hash + model` ([10](10.md)).
- **Rendered PDF** — keyed by `content_hash + strategy + stage`; skip re-render.

Cache lives under `out/<slug>/_meta/cache/` (and an optional shared
`~/.cache/vexy-dex/`). This is a simple keyed file store — not a caching
framework ([01](01.md)). `--no-cache` forces fresh work.

## Determinism

Given a fixed localized page, strategy, and config, output is reproducible
([02](02.md)). The only non-deterministic input is the network fetch, isolated
in Stage 1 and frozen by the cache thereafter — so debugging a render never
requires hitting the network again.
